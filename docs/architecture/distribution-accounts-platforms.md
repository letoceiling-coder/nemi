# Установка, аккаунты и платформы

## 1. Установочный файл (.exe)
Да. Tauri 2 собирает установщики Windows: **NSIS `.exe`** (основной) и `.msi` (для корпоративного развёртывания).
- Один установщик ставит приложение на любой Windows 10/11 x64; цифровая подпись (code signing) обязательна, иначе SmartScreen предупредит.
- Python-backend упаковывается как **sidecar** (PyInstaller / embedded Python) внутри установщика — отдельно ставить Python не нужно.
- Ollama и модели **не** входят в установщик (десятки ГБ): при первом запуске мастер проверяет Ollama, предлагает установить и скачать модель под доступную VRAM. Qdrant — встроенный/локальный режим.
- Автообновление — Tauri Updater + подписанный манифест (Phase 8 ТЗ), данные пользователя при обновлении не затрагиваются.

## 2. Аккаунты, изоляция, объединение
Два уровня:
1. **Локальные аккаунты (на ПК).** Каждый аккаунт = отдельное пространство данных: своя SQLite-БД, своя коллекция Qdrant, свой префикс в S3 (`<bucket>/users/<id>/`), свои секреты в Windows Credential Manager (ключ `pai/<id>/…`). Агенты и плагины работают только в контексте текущего аккаунта; данные одного аккаунта недоступны другому на уровне путей и API (каждый запрос несёт `user_id` из сессии).
2. **Облачный аккаунт (опционально, позже).** Нужен для синхронизации между устройствами и мобильного клиента. Локальный аккаунт можно **привязать** к облачному.

**Объединение аккаунтов** — только явная операция «Привязать/слить»: предпросмотр (что и откуда переедет), подтверждение паролями обоих аккаунтов, дедупликация по ID записей, резервная копия обоих до слияния, откат. Автоматически аккаунты не сливаются.

В прототипе уже есть: регистрация/вход по почте и паролю (PBKDF2-хэш), несколько аккаунтов на ПК, изоляция ключей настроек по `userId`. Реальная изоляция данных появится вместе с бэкендом (Phase 1).

## 3. Платформы
| Платформа | Формат | Что доступно |
|---|---|---|
| **Windows 10/11** | Tauri-приложение, локальный backend, Ollama | Всё: управление окнами (UI Automation), захват аудио (WASAPI), экран, браузеры |
| **macOS** | Tauri-приложение (тот же UI и backend) | Всё, кроме Windows Control Layer: он реализуется заново через Accessibility API / ScreenCaptureKit / CoreAudio. Нужна нотаризация Apple |
| **Android / iPhone** | Tauri 2 Mobile либо PWA — **клиент-компаньон** | Чат, задачи, проекты, почта, уведомления, подтверждение действий. Модели, агенты и управление ПК **не** запускаются на телефоне: клиент подключается к вашему домашнему/рабочему ПК или серверу через защищённый канал (Tailscale/WireGuard или зашифрованный relay) |

Принцип: «толстый» клиент (backend + модели) — Windows, затем macOS; мобильные — «тонкие», работают через удалённый доступ к backend. Поэтому API уже проектируется как `/api/v1` с авторизацией и localhost-only по умолчанию, а удалённый доступ включается отдельно (п. 31.15 ТЗ).

Порядок: Windows → macOS (после стабилизации Phase 4, т.к. платформенные адаптеры) → мобильный компаньон (после Phase 5–6).
